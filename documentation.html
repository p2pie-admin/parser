Назначение модуля

Модуль parser запускает пачку воркеров, которые циклически скачивают XML-курсы обменников, форматируют их и складывают результаты в Redis/GraphQL-слои сервиса. Процесс разбит на главный поток, отвечающий за подготовку окружения и оркестрацию воркеров, и рабочие циклы, которые непосредственно обрабатывают обменники.

Главный процесс

  • start() (файл src/index.ts) — точка входа, которая либо запускает главный процесс, либо, в дочернем воркере, ждёт свою очередь и вызывает основной цикл loop().
  • startMainWorker() — выполняет runInitialization(), запускает обновление справочников через scheduleAllRatesIDRefresh(), подбирает свободные порты и форкает по числу CPU процессы-клонов. Также следит за падениями воркеров и рестартует их с экспоненциальной задержкой не более пяти раз.

Рабочий цикл

  • getGeneralData() (файл src/1_loop.ts) — кеширует результат prepareGeneralData() на интервал GENERAL_DATA_TTL_MS, чтобы воркеры не перегружали источники служебных данных.
  • loop() — бесконечно получает список обменников и их статистику из Redis, раз в big_loop итераций инициирует reload(), распределяет задания между воркерами с учётом весов getAdaptiveWorkerWeights(), затем ограничивает параллельность через p-limit и вызывает processSingleExchanger() для каждого обменника. После каждой итерации фиксирует пропуски updateStatusesBySkip() и ждёт паузу loopPause секунд.

Обработка обменников

  • processSingleExchanger() (файл src/2_exchangerProcessor.ts) — пропускает обменники по расписанию skip, скачивает их XML через httpGet, преобразует xmlToJson(), формирует курсы обработчиком RateFormatter и отправляет агрегированную статистику с помощью sendTotalRates(). Ошибки и предложения по увеличению интервала парсинга отправляются через sendExchangerError().
  • withTimeout() и ProcessingTimeoutError — обёртка, ограничивающая работу processSingleExchanger() значением PROCESS_TIMEOUT_MS. При таймауте воркер аккуратно повышает skip и сообщает о проблеме.

В сумме эти функции формируют устойчивый конвейер парсинга обменников, где главный процесс управляет воркерами, каждый воркер кэширует общие данные и разбирает свою часть обменников, а конкретная обработка защищена таймаутами и отчётностью.
